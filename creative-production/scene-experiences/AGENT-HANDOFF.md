## Deliver this sequence depth-first

1. Choose a real consuming surface and subject. Write a one-page director's treatment, the
   visitor's primary task, object/environment relationship, and an interaction that changes meaning.
   Compare a restrained editorial alternative, a 2.5D hybrid and live 3D before selecting the medium.
2. Produce a six-beat board (or fewer when sufficient): establish, approach, reveal, participate,
   change scale, resolve. Define camera, lighting, prop state, text, input, exit, reverse and fallback.
   A deliberate rest is valid; every scene does not need a toy. Keep the full page task accessible.
3. Create editable source masters locally. Illustrator/Photoshop are user-reported available;
   probe their installed automation interfaces and owned sessions. Use Blender for real spatial
   objects, and Remotion/AE/FFmpeg when time-based composition is the better route. Source other
   tools through existing approvals, with exact version and rights records. Never flatten the only source.
4. Build a vertical slice using one shared scene evaluator/state contract, semantic DOM and an
   appropriate renderer. Preserve selected materials and object identity across scene and route changes.
   Scroll is one driver, not the only input. No scroll interception, unskippable intros or false OS chrome.
5. Review actual frames and actual motion at intended placement size. Fix continuity, materials,
   type, occlusion and interaction weaknesses before adding extra effects. Compare the selected
   route to the simpler alternative using the same content and devices.
6. Extend the existing journey capture and Remotion/viewer paths. Test forward/reverse/fast seek,
   keyboard, touch, resize, deep links, hidden tab, pause, reduced motion, unavailable graphics,
   cancellation and source loss. Capture DOM/state **and** pixels. Keep raw evidence separate from
   edited presentation video; an authored frame is not a product screenshot.
7. Prove actual native save/close/reopen, export, consumer import and behavior. Run the real repo
   build and at least one shipped consumer, not only this package's inline fixture. Report specific
   blockers and continue ready work. Do not relabel a blocked GPU/native lane as verified.

## Scope and discipline

Target flagship pages, product demonstrations, learning narratives, spatial portfolios and
appropriate interactive product surfaces. A settings screen or urgent workflow still needs a
fast ordinary interface; scene direction is a capability, not a mandate for every screen.
Use accepted PhenoDesign branding. Apple/Nike are references for choreography, scale and
production discipline, not permission to reuse trademarks, assets or invented technical claims.

No focus theft, operator-document edits, microphone/camera/device-motion access without consent,
private uploads, unapproved spend, production credentials, automatic publication or global kills.
Use bounded concurrency and a foreground-reserved resource budget. One native app lease until
isolation is proved. Preserve evidence and operate within the repo's existing lifecycle vocabulary.

Return actual changed files, capability observations, source/recipe identities, target-device
results, failed tests, visual critique and corrected frames. Separate ART_DIRECTION_REVIEWED,
SOURCE_REOPENED, RENDERED, CONSUMER_TESTED and DEVICE_QUALIFIED observations; do not invent a
new product lifecycle or declare the full matrix implemented because files exist.
