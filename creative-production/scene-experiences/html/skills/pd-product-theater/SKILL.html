Product Theater

Trigger and objective

Turn actual product properties into an experiential narrative.

Inputs

Verified product facts or clearly labeled concept properties.

Workflow

Choose a property a visitor can understand by manipulation or change of scale. Stage an input-consequence loop, then return to useful configuration/comparison. Keep invented internals explicitly conceptual.

Read docs/DESIGN-DIRECTION.md from the canonical pack root. In a PhenoDesign checkout that root is creative-production/scene-experiences/; in the standalone ZIP it is the extracted V3 root. Read only the related docs/recipes, not every skill.

Deliver

Property-to-beat mapping, usable task exit, real source/content provenance.

Critical alternative / failure case

Reject false specifications and decorative mechanisms presented as real engineering.

Non-negotiable boundaries

Keep accepted design tokens, editable source and source rights. Work on owned files/sessions and within approved tool/spend/network scope. Capture actual outputs, report blocked backends honestly, and use the existing journey/evidence authority rather than an agent-authored success flag. A cheaper or less animated alternative wins when it preserves the same meaning and task with better results.
