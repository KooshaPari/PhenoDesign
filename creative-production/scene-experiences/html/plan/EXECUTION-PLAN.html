Implementation order

M0 · Reconcile current PhenoDesign and historical kits

Dependencies: none.

  • Read current owners, migration heads and installed work
  • Choose one implementation per adapter; retain newer changes

Reject: Do not run both v2 overlays or rename root directories.

M1 · Approve treatment and scene contract

Dependencies: M0.

  • Real subject/task, alternatives and source provenance
  • Scene board with direct/reverse/fallback behavior

Reject: Do not equate a rotating asset with a world.

M2 · Author and reopen native masters

Dependencies: M1.

  • Illustrator/Photoshop owned native canaries
  • Blender named optical/material source saved and cold-reopened

Reject: Installed app or generated script is not source reopen proof.

M3 · Integrate one actual scene consumer

Dependencies: M1.

  • Use accepted tokens and semantic UI
  • Real pointer/keyboard/touch affect scene and environment
  • Reverse/resize/direct-entry preserve selection

Reject: Inline fixture cannot pass served-product gate.

M4 · Complete Remotion cross-media path

Dependencies: M2, M3.

  • Same state/timing drives real render
  • Decoded frames and annotation crop timing verified
  • Actual docs/player consumer exercised

Reject: Authored film is not raw journey evidence.

M5 · Extend existing journey validation

Dependencies: M3.

  • Capture actual states and pixels; retain errors
  • No-JS/motion-off/rich-render-failed cases tested

Reject: No new proof registry or app self-PASS authority.

M6 · Qualify real devices and native isolation

Dependencies: M2, M4, M5.

  • Target Windows/NVIDIA and Mac/mobile browser results
  • No focus theft or shared-native-document collisions
  • Measure budgets, hidden/offscreen, disposal and cancellation

Reject: Headless/software results are not hardware qualification.

M7 · Critique and refine the entire sequence

Dependencies: M3, M5.

  • Inspect full motion and placement-sized frames
  • Repair weakest craft dimension with evidence
  • Compare simpler alternate rendition

Reject: No score average hides a mandatory failure.

M8 · Prove second consumer and extract only common logic

Dependencies: M6, M7.

  • Two independent real consumers use accepted shared source
  • No duplicate source/worker/evidence ownership
  • Version/public exports and migration documented

Reject: Do not publish an abstract engine before shared needs exist.

These are proposed assignments; import them into the existing owner. The standalone kit does not claim these repo milestones complete.
