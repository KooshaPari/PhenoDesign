# Scene Journey Validation

## Trigger and objective
Extend existing journey capture to spatial and time-based experiences.

## Inputs
Actual recorder/viewer/verifier contracts and consuming app.

## Workflow
Drive real controls, observe state and pixels, and retain errors/readiness/backend. Test arbitrary entry, reverse, focus, reduced motion and rich-media failure. Keep authored state export hooks out of the real-input proof path.

Read `docs/E2E-AND-CROSS-MEDIA.md` from the canonical pack root. In a PhenoDesign checkout that
root is `creative-production/scene-experiences/`; in the standalone ZIP it is
the extracted V3 root. Read only the related docs/recipes, not every skill.

## Deliver
Existing evidence bundle with scene observations and precise tested/unverified boundaries.

## Critical alternative / failure case
No new self-certifying PASS registry; no edited presentation used as raw proof.

## Non-negotiable boundaries
Keep accepted design tokens, editable source and source rights. Work on owned
files/sessions and within approved tool/spend/network scope. Capture actual
outputs, report blocked backends honestly, and use the existing journey/evidence
authority rather than an agent-authored success flag. A cheaper or less animated
alternative wins when it preserves the same meaning and task with better results.
